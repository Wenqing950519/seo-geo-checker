# 學習規則（細則）

> 本檔是 `CLAUDE.md` / `AGENTS.md` 的 Learning Protocol 與 Anti-Dependency Rule 細則。

## 適用時機

任務涉及以下任一項時，**必須**走完整學習流程，不得直接產出方案：

- 研究設計
- 產品判斷
- 商業分析
- 資料解讀
- 核心架構

例外：使用者明確說「純執行」「照做就好」「不用解釋」。

## 五步流程

1. **確認理解** — 先問使用者目前怎麼看這件事、有什麼假設
2. **指出漏洞** — 說明其中的未知條件、替代解釋、可能的錯誤前提
3. **解釋原理** — 講清楚判斷依據，不只給答案
4. **等待確認** — 關鍵決策交由使用者拍板
5. **才開始實作**

## 任務結束後的必要說明

每次重要任務完成，簡要回答五件事：

- 這次做了什麼
- 為什麼這樣做
- 使用者應理解的核心概念
- 哪些部分仍需人工驗證
- 建議記入 `docs/LEARNING_LOG.md` 的內容

## 建議與決策必須分開

用詞要能一眼分辨：

| 情境 | 正確表述 |
|---|---|
| Agent 的想法 | 「**建議**：⋯⋯」「一個選項是⋯⋯」 |
| 使用者已拍板 | 「依 `DECISION_LOG.md` D-XXX，**已確認**⋯⋯」 |
| 尚未決定 | 「這需要你決定，因為屬 Human Ownership」 |

**未記錄於 `docs/DECISION_LOG.md` 的方向，一律不得稱為「已決定」。**

## Anti-Dependency 檢查

若使用者無法自行解釋某項核心設計，**先補足理解，不要繼續堆疊複雜度**。

參考 `docs/LEARNING_LOG.md` 的自我檢查表，包含：主要架構、V3 權重理由、unknown vs 0、資料流、測試範圍、分數限制、usage ledger 分離原因。
