## 0. 專案定位與優先序 `[已確認 2026-07-26]`

**目的優先序**

```
研究白皮書  >  能力展示  >  商業化
```

- 原本設想 OPC（一人公司）路徑，評估後認為難度過高。
- 現階段以**創業競賽**為嘗試場域（**標的未鎖定**，因此不構成硬時程約束）。
- 商業化不放棄：若成功，將回頭成為能力展示的強力佐證。

**研究所路徑** `[已確認]`

- 時間點：2028 年 1 月 或 2028 年底。
- **時程不是重點。** 重點是方法論的累積性——「一次比一次完整、優秀、硬核，且不閉門造車」。
- 意涵：白皮書必須依 `docs/RESEARCH_STANDARD.md` 全套規格撰寫，不因可讀性打折。

## 1. 產品定義

**一句話定位** `[待定 — 待 P2 構念定義後回填]`

現行對外說明（出自 `docs/CURRENT_STATE.md`，屬既有陳述、**尚未升格為正式定位**）：

> GeoCheck 量測的是「品牌在指定 Perplexity 查詢集下的可觀測 GEO 證據」，不是全網 AI 搜尋保證、不是傳統 SEO 排名、也不是主觀觀感分數。

> [!warning] 為何暫不定稿
> §4 主軸確認為「可見度**應如何定義**」——亦即「可見度」這個構念目前**尚未被定義**。
> 在 P2 完成構念定義前，任何一句話定位都只是對現有實作的描述，不是對產品的定義。
> **回填時機**：P2 產出構念定義後。

**產品邊界 — 明確不做什麼** `[已確認 2026-07-26]`

- **不承諾獲客或效果。** 量的是可見度，不是業績。此為硬邊界，不得因行銷需要鬆動。
- **不做內容代寫與執行。** 只診斷，不動手改客戶網站。

> [!caution] 與 §6 的未解衝突
> 本條與 §6 曾考慮的「付費改善服務」直接矛盾。使用者於 2026-07-26 表示商業模式尚未想清楚，故 §6 標為未定，**本邊界暫時成立**。若日後決定販售執行服務，必須先修改本條並記入 `DECISION_LOG`。

**未納入邊界的項目**（訪談中未選，代表**保留彈性**，非已排除）

- Google 傳統排名檢測
- Perplexity 以外的生成式引擎（ChatGPT / Gemini / Claude）

## 2. 目標對象

> [!important] 本節分為兩類對象
> 訪談中發現「產品使用者」與「研究讀者」是不同的人，強行合併會迫使白皮書在嚴謹度與可讀性之間二選一。
> 解法：**一份研究、兩種輸出**——嚴謹白皮書為正本，客戶版摘要由正本裁切，摘要不得新增正本沒有的主張。

### 2.1 產品使用者 `[假設 — 無第一手證據]`

**中小企業主本人**（非行銷負責人、非代理商）

- 使用者自陳依據為「個人判斷」，**未經訪談或第一手接觸驗證**。
- 產業偏好：餐飲（使用者自陳為**臆測**，見 §4 H-005）。
- 依 `RESEARCH_STANDARD` 主張分級，本項為 **Assumption**，不得在對外文件中寫成已驗證客群。

### 2.2 研究讀者 `[已確認]`

依重要性排序：

1. **具研究訓練的外部檢驗者**（教授、資深同行）——白皮書嚴謹度的定錨對象。
2. **創業競賽評審**——讀摘要與方法論章。
3. **潛在客戶（中小企業主）**——讀客戶版摘要，不讀正本。

## 3. 核心問題與證據

### 3.1 使用者的推論鏈 `[假設鏈 — 全部未驗證]`

```
A1  vibe coding 興起 → 代建網站成本大幅降低
A2  建站成本降低     → 中小企業更願意花錢建站
A3  企業建站的初衷   → 獲客
A4  網站被 AI 引用   → 獲客                    ← 斷點
A5  餐飲是提升最大、最容易被打動的市場
```

### 3.2 各環節評估 `[推論]`

| 環節 | 可驗證性 | 評估 |
|---|---|---|
| A1 | 高（接案平台行情、AI 建站工具定價、年度對比） | 使用者已自行標註待驗證 |
| A2 | 中 | **供給變便宜 ≠ 需求增加**；也可能是同一批人付更少錢，總市場未擴大 |
| A3 | 高（可訪談） | 大致可信，但亦可能是「同業都有」「形象需求」 |
| **A4** | **低** | **斷點，見 §3.3** |
| A5 | 中（可用現有量測管線做小樣本跨產業測試） | 使用者已自行標註為臆測 |

### 3.3 A4 斷點 — 本專案最重要的未解問題 `[已確認為待解]`

**問題**：GeoCheck 量的是**可見度（被引用）**，中小企業主要的是**業績（客人上門）**。中間缺一條證據。

**且與現有對外聲明衝突**：`docs/CURRENT_STATE.md` 已明載「不保證任何 AI 引擎一定引用、排名或推薦」，而 A4 正是被該聲明排除的那句話。

**處置** `[已確認 2026-07-26]`：白皮書補一段**探索性相關分析**（見 §4 H-004）。

**必須事先承認的四項限制**（不得在白皮書中略過）：

1. **資料取得**——第三方網站真實流量不可得，只能用 Similarweb / Ahrefs 等代理指標，中小型網站精度差。
2. **反向因果**——大品牌流量高，同時也較易被引用；此為共同原因，非「引用造成流量」。
3. **混淆變數**——品牌知名度、既有 SEO 體質、廣告預算三者同時影響引用率與流量，樣本量不足以控制。
4. **時間方向**——橫斷面相關無法推論因果；因果需前後測設計。

**結論**：此分析只能報告「觀察到／未觀察到相關」，**禁止宣稱因果**。

### 3.4 尚缺的證據 `[待補]`

- 無任何第一手使用者訪談紀錄。
- 無競品或替代方案盤點。
- A1–A5 全部未驗證（使用者決定 2026-07-26 暫不驗證，優先完成 charter）。

### 4.2 專案層研究主軸 `[已確認 2026-07-26 — 定稿]`

> **品牌在生成式引擎中的「可見度」應如何定義與操作化，才能得到有效度且可複現的測量？**

**為何是這一題**：本專案目前所有核心困難，都是同一個缺口的症狀——**構念（construct）從未被定義，卻已經在操作化（`geo-assessment.js` 已在計分）**。

| 症狀 | 根源 |
|---|---|
| 權重 50/30/20 無推導依據 | 不知構念有幾個面向、何者更能代表它 |
| `unknown` vs `0` 的爭議 | 「沒被提及」是可見度低，還是沒測到？構念與測量混淆 |
| 說不出「什麼算 GEO 表現好」 | 無構念即無判準 |
| Hunterest 站內 87 但 Perplexity 0 | **效度問題**：站內準備度測到的可能不是可見度 |

**對應階段**：P1 盤點現有操作化 → P2 補上構念定義並重新推導 → P3 實作。

## 5. 評分框架的定義權

**狀態**：`[待定 — 由 P2 重新推導]`

歷史演算法 V3.0.0 有**兩層**權重，**兩層皆無推導依據**：

| 層級 | 位置 | 公式 |
|---|---|---|
| 外層 | `mock-api/lib/geo-assessment.js:26` | `technical × 0.2 + citeability × 0.3 + perplexity × 0.5` |
| **內層** | `mock-api/lib/perplexity-visibility.js:105` | `mentionRate × 40 + citationRate × 30 + authority × 0.3` |

> [!warning] 內層權重先前未被記錄於任何文件
> 內層佔總分 50%，影響更大，但 `ALGORITHM_V3.md` 與 `DECISION_LOG.md` 皆未提及。
> 此類「隱性決定」的完整盤點列為 **P1** 的產出。

**依 `RESEARCH_STANDARD §12.2`**（權重不得任意設定），現行值不可用於對外結論。

**處置**：V3 權重保留為歷史未經校準值。產品 v1 已依 D-021 另定 65%／35% 基線，見 `docs/AI_TRUST_INDEX_V1.md`；該基線仍不是外部效度已完成的科學閾值，白皮書不得只靠產品分數提出結論。

**設計原則（方向同意，細節 P2 再議）** `[已確認方向 2026-07-26]`

**量測層／分析層分離**：

```
量測層 Measurement Layer（穩定，跨篇不變）
  只產出原始訊號，不合成分數
  · 是否提及品牌（bool）· 是否引用官網（bool）
  · 引用來源網域（list）· 站內技術訊號（raw）· 內容特徵訊號（raw）
        ↓ 同一批原始資料
分析層 Analysis Layer（每篇白皮書可變）
  各篇依自身 RQ 決定如何分析
```

**推論**：權重從量測層消失，只在「需要給客戶單一數字」時出現——即**權重是產品層問題，不是研究層問題**。現行架構將兩者綁死於 `geo-assessment.js`，是權重爭議的結構性根源。

## 7. 成功與失敗的定義

### 成功 `[已確認 2026-07-26]`

1. **方法論完整到能與教授對談。** 不只是能報告結果，而是能就研究設計本身進行學術討論。
2. **受過外部檢驗。** 不閉門造車——至少一位外部專業讀者認真讀完並提出批評意見。
3. **達到 L2 可複現性。** 原始資料可被第三方取得。

**可複現性三層級**（供自我檢驗）

| 層次 | 定義 | 現況 |
|---|---|---|
| L1 計算可複現 | 同一份原始資料重算得同樣結果 | ✅ 有資料集 SHA-256、題庫凍結、run ID |
| **L2 資料可取得** | 第三方拿得到原始資料 | ❌ `research-input/` `research-output/` 被 `.gitignore` 排除 → **列為成功條件** |
| L3 獨立可重製 | 他人依方法重新收資料得相似結論 | ❌ 尚未嘗試（未列入本階段成功條件） |

## 8. 已知限制
