# 下一步 Roadmap：路徑全面分析

> [!caution] 本檔不決定任何事
> 依 `CLAUDE.md` Human Ownership，商業模式與產品優先級由使用者決定。
> 本檔的作用是**讓選擇變得可比較**，不是替你選。

## 0. 先回應你的三點（含我上一版的錯誤）

### 0.1 「公開權重不具護城河」——你是對的，我上一版錯了

我在 `COMPETITIVE_INTEL` §6 的 W-2 把「方法論可稽核」列為 wedge。這是錯的，錯在**我把研究資產當成商業資產**。

方法論透明能產生價值，需要三個條件同時成立：

| 條件 | GeoCheck 現況 |
|---|---|
| 有一群人**有能力**評估方法好壞 | 有（教授、資深同行）——但這群人**不付錢** |
| 這群人**有動機**評估 | 只有在他們要引用你、審你、或跟你合作時 |
| 被評估後的認可**能轉移**給付費者 | ❌ **斷鏈**。商家不會因為某教授說你方法嚴謹就付錢 |

第三條斷了，整條就斷了。**方法論嚴謹是 Charter §7「成功定義」的一部分，不是商業護城河。** 我把兩者混在同一個建議裡，這是分析錯誤，不是措辭問題。

**修正後的定位**：方法論嚴謹度對「路徑 1（研究）」是**核心交付**，對「路徑 2（agency 工具）」是**次要加分**，對「路徑 4（賣給商家）」是**零價值**。它從來不是 wedge。

### 0.2 「我沒有權威，誰認可我？」——這題有解，但解不在你身上

你把「權威」預設成**個人屬性**（背景、資歷、機構）。這條路你確實走不通，而且六個月內不會通。

但公信力還有第二種來源：**覆蓋率**。

| 權威來源 | 需要什麼 | 你有嗎 |
|---|---|---|
| 個人資歷 | 學歷、機構、年資、客戶名單 | ❌ 六個月內無解 |
| **資料覆蓋率** | 「我實測了 X 個樣本、Y 個平台、Z 次」 | ✅ **藍圖已寫好：100 店 × 3 平台 × 516 次** |

「我是誰」不可辯論，「我測了 516 次」可以被檢驗、被複製、被引用。**沒有人能因為你是學生就說 516 次沒發生過。**

米其林指南沒有廚師資歷。它的權威來自**每年都去吃、都用同一套規則、都公開結果**。Ahrefs 的 DR 沒有學術背書，它的權威來自**爬了全網**。

→ 這不是「你也可以有權威」的心靈雞湯。這是一個具體的替代機制，而且**你已經有一半的實作藍圖了**（`2026_台灣餐飲_AI搜尋能見度_白皮書研究藍圖.md` + D-022 Confirmed）。

### 0.3 「權重能代表甚麼？」——目前什麼都不代表，你說得對

直接回答：**現在的分數沒有意義，而且不是因為權重沒推導，是因為它沒有被證明會動。**

一個分數要有意義，只有兩條路：

| 路徑 | 需要什麼 | 現況 |
|---|---|---|
| **構念效度**（學術路） | 定義「可見度」是什麼 → 論證這些指標代表它 | Charter §4.2 已列為 P2 主軸，**尚未做** |
| **介入反應性**（實用路） | 做了建議 → 分數變 → 真實提及率也變 | **零筆紀錄** |

**這是 GeoCheck 目前最大的空洞，比缺功能嚴重得多。**

`docs/CURRENT_STATE.md` 的最終演算法審計只有兩筆橫斷面資料（壽司郎 65／Hunterest 41）。沒有任何一筆「同一個網站，改了什麼，分數與提及率怎麼變」。

這代表：

- 對商家：無法回答「我照做會怎樣」——這正是你點 2 說的「商家只在乎能不能增加曝光」。**你現在不能回答這題。**
- 對 agency：無法回答「這工具能幫我證明我做的事有用嗎」
- 對研究：構念效度缺一塊
- **對你自己**：你不知道自己給的建議是否有用

**而這是所有缺口裡最便宜的一個。** 不需要新功能、不需要新演算法、不需要買競品。用你自己的站 + 2–3 個願意配合的站，基線 → 改 → 重測。管線已經有了。

> 【建議】不管最後選哪條路徑，這件事都要做。理由見 §4「無悔動作」。

### 0.4 但你的點 2 有一個我要反駁的地方

> 「商家只在乎能不能透過我的工具增加曝光度甚至增加變現」

**這句話對「成效工具」成立，對「評鑑／指數」不成立。**

反例（都是商家會付錢、但都不承諾營收的東西）：

| 產品 | 承諾營收嗎 | 商家在乎嗎 | 為什麼 |
|---|---|---|---|
| 米其林／500盤 | ❌ | ✅ 極度在乎 | **別人看得到**，且**競爭對手在榜上** |
| Ahrefs DR / Moz DA | ❌ | ✅ | 業界共用語言，會被寫進提案與報價 |
| ISO / 各種認證 | ❌ | ✅ | 缺了會被扣分 |
| 保險 | ❌（純成本） | ✅ | 恐懼，不是收益 |

商家付錢的三個真實理由：**貪（能賺）／怕（會失去）／面子（別人看得到）**。你一直只在攻第一個，而第一個正好是 Charter §1（D-007 Confirmed）明文禁止你承諾的那個。

→ **這就是 GeoCheck 的根本矛盾**：你的 Charter 邊界（不承諾獲客、只診斷）天生適合「評鑑／指數」模式，但你一直試圖把它做成「成效工具」（monitoring SaaS）。兩者要的證據、通路、定價、護城河**完全不同**。

這不是措辭問題，是路線問題。§3 會把兩種模式攤開比。

## 1. 為什麼「Roadmap」現在還畫不出來

在決定做什麼之前，有三個前提未決。**任何在前提未決時畫的 roadmap，都只是把選擇偷偷做掉。**

| # | 未決前提 | 現況 | 誰能決定 |
|---|---|---|---|
| **P-1** | 這個專案的**第一目的**是什麼 | Charter §0（D-004 Confirmed）：研究白皮書 > 能力展示 > 商業化。**但你這兩次對話都在問商業化。** | 只有你 |
| **P-2** | 買家是誰 | Charter §2.1 假設中小企業主〔未驗證〕；D-023 已據此改文案；但你第一則訊息說 ICP 是 agency/consultant | 只有你（且**需要 P-3 的證據**） |
| **P-3** | 產品承諾什麼 | Charter §1（D-007）：不承諾獲客、不做執行。你的點 2 說商家只在乎變現 → **兩者不相容** | 只有你 |

**P-1 是最上游的。** 因為：

- 若 P-1 = 研究／升學／競賽 → 商業化是副產品，roadmap 是白皮書與資料集，**競爭格局幾乎不影響你**
- 若 P-1 = 收入 → 你必須先承認 Charter §0 的優先序要改，且第一件事不是寫程式，是**接觸買家**（Charter §3.4 已列「無任何第一手使用者訪談紀錄」為待補，至今未補）

> 我不會替你決定 P-1。但我要指出一件事：**你目前的行為（問競品、問 SaaS 轉型、問 roadmap）和 D-004 記錄的優先序不一致。** 這不代表你錯，可能代表 D-004 該更新了。但它需要被明確更新，不是默默漂移。

## 2. 缺的到底是什麼（診斷）

把「還缺什麼」按**取得成本**排序，而不是按功能清單排序：

| 缺口 | 嚴重度 | 取得成本 | 現在能做嗎 |
|---|---|---:|---|
| **介入證據**（改了 → 動了） | 🔴 最高 | **極低**（管線已有） | ✅ 立刻 |
| **第一手買家接觸**（5–10 次訪談） | 🔴 最高 | **低**（只花時間） | ✅ 立刻 |
| 構念定義（P2） | 🟠 高 | 低（純寫作） | ✅ 立刻 |
| 縱貫資料（同 cohort 多波） | 🟠 高 | 中（付費 API） | ⚠️ D-022 已核准範圍 |
| 帳號／訂閱／持續監測 | 🟡 中 | 中（工程） | ⚠️ 前提未決前先別做 |
| 多引擎 | 🟢 低 | 高（API 成本） | ❌ 見「不要做」清單 |
| 內容生成 | 🟢 低 | 高 | ❌ 撞 D-007 |

**關鍵觀察**：前三個最嚴重的缺口，**成本全部接近零，而且全部不需要寫任何新功能。**

你上一次問我「要做什麼功能」，但你真正缺的東西一個功能都不是。

## 3. 四條路徑的全面分析

> 四條不是互斥的，但**六個月內同時做兩條以上 = 一條都做不完**。
> 每條路徑列出：假設／買家／付錢理由／證據門檻／6 個月 roadmap／成本／Charter 相容性／失敗訊號／被消滅難度。

---

### 路徑 1：研究資產優先（維持 D-004 原路）

**核心假設**：白皮書與方法論的累積，本身就是目標（升學／競賽／能力展示），商業是副產品。

| 項目 | 內容 |
|---|---|
| **買家** | 無（不變現） |
| **付錢理由** | N/A |
| **證據門檻** | **最高**——學術可辯護、L2 可複現、外部檢驗者讀完並批評（Charter §7） |
| **成本** | 低（自有樣本＋已核准的 D-022 範圍） |
| **Charter 相容** | ✅ **完全相容**，這就是 D-004 |
| **被競品消滅難度** | **不適用**——競品不跟你搶這個 |

**6 個月 roadmap**

| 月 | 交付 |
|---|---|
| 1 | P2 構念定義（Charter §4.2 主軸）。純 `.md`，不碰 code |
| 1–2 | 依構念重新推導權重（或決定**不要總分**，只報原始訊號） |
| 2–4 | 執行 D-022 信義區 cohort 第 1–2 波，依藍圖 SOP |
| 4–5 | 第 3 波 + 盲式編碼 + 鎖數分析 |
| 5–6 | 白皮書撰寫；找 1 位外部檢驗者實際讀完 |

**失敗訊號**：找不到任何外部檢驗者願意讀；或三波資料一致性極低（Jaccard 過低）導致無法下任何結論。

**這條路的真實代價**：六個月後你有一份好白皮書和零收入。若你的 runway 或動機撐不住，這條路會在第四個月自然死亡——而**死在第四個月比不開始更糟**，因為 cohort 斷掉的縱貫資料沒有價值。

### 路徑 2：Agency／顧問底層工具（你第一則訊息的 ICP）

**核心假設**：台灣 SEO/GEO 顧問與小型 agency 需要一個能同時管多客戶的 AI 能見度工具，且現有工具服務不好。

**為什麼這條路繞開了你的點 2**：agency 買的不是「我的曝光增加」，是「**我能對我的客戶交代**」。他們的 JTBD 是贏提案、做月報、證明自己有在做事。**這是一個不需要你證明 ROI 的買家。**

| 項目 | 內容 |
|---|---|
| **買家** | Agency 老闆／獨立顧問（不是他們的客戶） |
| **付錢理由** | 怕（客戶問「AI 有沒有推薦我」答不出來）＋ 省（不用手動跑）＋ 面子（報告好看） |
| **證據門檻** | **低**——agency 自己會判斷好不好用，不需要你證明效果 |
| **成本** | 中（要做帳號、多專案、白標、台幣金流） |
| **Charter 相容** | ⚠️ **需要改 D-023**（商家白話 → 專業術語）與 Charter §2.1 |
| **被競品消滅難度** | 🔴 **低**。Hogiah 只要把「1 個網域」改成「N 個網域」就消滅大半立論（見 `COMPETITIVE_INTEL` S002） |

**6 個月 roadmap**

| 月 | 交付 |
|---|---|
| **0（阻塞）** | **訪談 5–10 位台灣 agency／顧問。沒有這一步，後面全部是猜的。** |
| 1 | 依訪談決定：白標？月報 PDF？CSV？多客戶儀表板？定價單位？ |
| 2–3 | 帳號系統 + 多專案 + 台幣金流（綠界／藍新） |
| 3–4 | 白標報表 + 排程重跑 |
| 4–6 | 5–10 個 design partner 免費用，換使用資料與案例 |

**失敗訊號**：訪談中 5 人以上說「我用 Hogiah／Ahrefs 就夠了」或「我客戶不問這個」→ 立刻停。

**這條路的真實風險**：台灣專職 GEO/SEO agency 的數量是有限的。即使全拿下，天花板可能只有數十家 × 每月數千元。**這是一個能活但很難長大的生意**，而且 Hogiah 的分潤計畫（10–20% 經常性）正在把同一批人變成它的銷售通路。

### 路徑 3：垂直普查 → 指數／評鑑（**你已經鋪了一半**）

**核心假設**：在單一產業做到高覆蓋率的定期實測，覆蓋率本身取代個人權威；被納入評鑑的商家會在乎自己的位置。

**這條路直接回應你的三點**：

| 你的質疑 | 這條路的回答 |
|---|---|
| 我沒有權威，誰認可我 | 權威來自「信義區 100 家 × 3 平台 × 516 次」的**覆蓋率**，不是你的背景 |
| 權重能代表什麼 | 排名不需要總分。**EMR、SoV、Prominence 是原始可觀測量**，不需要權重（藍圖 §F 已這樣設計） |
| 商家只在乎變現 | 商家在乎的是「**我的競爭對手在榜上，我不在**」。這是怕＋面子，不是承諾營收——**且完全不牴觸 D-007** |

**你已經有的**（這是這條路最強的理由）：

- ✅ D-022 **Confirmed**：信義區餐廳 H2 2026 cohort 追蹤，觀測窗 2026-09-03～12-31
- ✅ `2026_台灣餐飲_AI搜尋能見度_白皮書研究藍圖.md`：抽樣框（TFDA 食品業者登錄）、分層規則、516 次測試矩陣、SOP、編碼欄位、統計方法全部寫好
- ✅ `2026_台灣餐飲_AI搜尋能見度_信義區140家候選池.md`：候選母體
- ✅ 量測管線（`geo-measurement.js`）、D1 報告儲存、run ID、資料集雜湊

| 項目 | 內容 |
|---|---|
| **買家（多層）** | ① 被評鑑的餐廳（報告／諮詢）② 餐飲業 agency（名單與洞察）③ 媒體／公協會（引用）④ 未來擴充到其他產業 |
| **付錢理由** | 怕（競爭對手在榜上）＋ 面子（公開排名）＋ 好奇（我幾分） |
| **證據門檻** | **中**——需要覆蓋率與方法一致性，**不需要 ROI 證明** |
| **成本** | 中～高。藍圖要求**實際 UI 操作**（ChatGPT 網頁搜尋、Perplexity 網頁、Google AIO），不用 API 代替 → **這是大量人時，不是 API 費用** |
| **Charter 相容** | ✅ 研究層與 D-022、D-007 相容。⚠️ **商業層需要新決策**（見下方警告） |
| **被競品消滅難度** | 🟢 **高**。Hogiah／Peec／Ahrefs 全部用 API 跑，**沒有人做真實 UI 的產業普查**。這件事的成本結構對 SaaS 不划算，對單人研究者划算 |

> [!warning] D-022 的決策邊界必須先處理
> D-022 明文：本研究「**不產生餐廳改善建議或因果結論**」。
> 所以「普查資料 → 商業化」**不是自動的**。要嘛研究版與商業版分離（同資料、不同輸出、不同揭露），要嘛修改 D-022。
> 這是新決策，屬 Human Ownership。**Agent 不得直接把研究資料拿去做商業排行榜。**

**6 個月 roadmap**

| 月 | 交付 |
|---|---|
| 1 | 凍結 sample_v1 / prompt_v1 / codebook_v1（藍圖 SOP 01–03）；決定研究版／商業版的分離規則 |
| 1–2 | 第 1 波 172 次測試（探索 72 + 品牌 100）；原始封存 |
| 2–3 | 第 2 波；15% 雙重編碼一致率 |
| 3–4 | 第 3 波；鎖數分析；Wilson CI |
| 4–5 | 白皮書（路徑 1 的交付**同時完成**） |
| 5–6 | 商業層測試：把個別餐廳結果做成單店報告，找 **10 家**實際接觸，看有沒有人願意付錢 |

**失敗訊號**：
- 三波 Jaccard 過低 → AI 回答不穩定到無法建立排名 → **整條路徑死亡**（這也是重要的研究發現）
- 接觸 10 家餐廳，0 家願意付任何金額 → 商業層不成立，但研究層仍成立

**這條路最大的優點**：**路徑 1 和路徑 3 的前 5 個月工作是同一份。** 你不需要在「研究」和「商業」之間二選一——先做普查，第 5 個月時你會同時擁有白皮書和一份可測試商業假設的名單。

**這條路最大的風險**：H-005（餐飲業落差最大、最易被打動）在 Charter 中標為「使用者臆測」，**至今未驗證**。若餐飲業老闆根本不在乎 AI 怎麼說，整個商業層歸零（研究層仍有價值）。

### 路徑 4：診斷 → 顧問服務（放棄 SaaS）

**核心假設**：不做產品，做服務。免費診斷當入口，賣人的時間。

| 項目 | 內容 |
|---|---|
