# 白皮書持續發展前提下的產品競爭力建構

> 前提（依你的指定）：白皮書研究**會持續發展**。本檔只回答一件事——
> **在這個前提下，產品層要怎麼長，才能長出競品用功能補丁補不掉的東西。**

---

## 1. 核心命題

**GeoCheck 的產品競爭力不會來自功能，會來自「母體」。**

所有競品（Hogiah、Peec、Profound、Ahrefs、Semrush、Scrunch、Otterly）的資料結構是同一種：

```
單一客戶 × 該客戶自選的 prompts × 時間
```

這種資料**只服務那個客戶，不累積**。客戶走了，資料就沒用了。所以他們必須靠功能競爭——引擎數、prompt 數、文章篇數。這是一場你打不贏的仗（`COMPETITIVE_INTEL` §8.3）。

白皮書藍圖產生的是另一種結構：

```
一個完整母體（信義區 100 店）× 凍結題庫 × 多波時間
```

這種資料**不屬於任何單一客戶，而且每多一波就更值錢**。

差別在一個字：**分母**。

競品能告訴客戶「你的分數是 41」。**沒有一家能告訴客戶「41 在你的同業裡是第幾名」**——因為他們沒有同業的資料。

> 這一句就是整份策略的全部。以下都是它的展開。

## 2. 白皮書自動生產哪些產品資產

以下**全部**來自 `2026_台灣餐飲_AI搜尋能見度_白皮書研究藍圖.md` 已規劃的欄位，**不是新增工作**。

| # | 白皮書產出 | 藍圖出處 | 產品層用途 | 競品給得出嗎 |
|---|---|---|---|---|
| **A1** | **母體分佈**（EMR、SoV、Prominence 的全母體分佈） | §F 能見度 | **百分位排名** | ❌ 無母體 |
| **A2** | **實體真值表** restaurant_master（官方名、別名、分店、地址、菜系、價位、營業、訂位＋來源日期） | §D-03 | **事實正確性比對** | ⚠️ 只能比對客戶自填 |
| **A3** | **引用來源結構**（source_type：官方／地圖／訂位目錄／媒體／UGC，含 supports_mention） | §E citation | **產業級引用地圖** | ❌ 無產業樣本 |
| **A4** | **事實正確率**（地址／菜系／價格／營業／訂位 × correct/partial/incorrect） | §E fact_check | **幻覺告警（有真值）** | ⚠️ 無獨立真值 |
| **A5** | **平台差異**（三平台 Jaccard、Kendall τ、UpSet） | §F 證據／品質／穩定 | **引擎選擇依據** | ❌ 無跨平台實測 |
| **A6** | **母體時間漂移**（三波） | §D 時間控制 | **對照組校正** | ❌ **這是最強的一項** |
| **A7** | **觸發率**（answer_generated / web_search_used / aio_triggered） | §E trigger | **「查不到」與「沒提到」的分離** | ⚠️ 多數混為一談 |

**A6 值得單獨說明。**

所有競品的儀表板都會告訴客戶「你的分數從 41 掉到 38」，並暗示是客戶做錯了什麼。

但沒有母體，就**無法區分「你退步了」和「整個產業都退步了」**——這在統計上就是缺對照組。若某次模型更新讓所有餐廳的提及率下降 15%，競品的客戶會看到自己掉分並焦慮，而 GeoCheck 可以說：

> 「你 −3，同區母體中位數 −5。你其實**相對進步**了。」

**這句話競品說不出來，而且不是因為他們技術不足，是因為他們的資料結構裡沒有母體。** 這是結構性的，不是功能性的。

## 3. Dashboard 具體構想

### 3.1 設計原則（三條硬規則）

| # | 規則 | 理由 |
|---|---|---|
| **R1** | **主指標是「位置」，不是「分數」** | 分數需要權重（Charter §5 未決、你質疑得對）；**位置不需要權重**。EMR 排名是原始可觀測量 |
| **R2** | **每個數字都必須有分母，且分母要顯示** | `RESEARCH_STANDARD §10.3`；同時這正是競品做不到的地方，要把它放在最顯眼處 |
| **R3** | **只陳述事實與缺口，不承諾結果** | Charter §1（D-007 Confirmed）。「你的競爭對手有 X，你沒有」是事實；「做了 X 會增加曝光」是承諾 |

### 3.2 五層結構

```
┌─ L0 位置 ────────────────────────────────────────────┐
│  你在【信義區・日式料理・23 家】中排第 17            │
│  提及率 8.7%（母體中位數 21.4%）    分母：18 次有效  │
│  ▓▓▓░░░░░░░  第 26 百分位                            │
└──────────────────────────────────────────────────────┘
┌─ L1 相對變化（第 2 波起才出現）──────────────────────┐
│  你      −3.2pp        母體中位數  −5.1pp            │
│  → 相對母體：+1.9pp（相對改善）                      │
│  [ 這一季整個母體下降，非個別現象 ]                  │
└──────────────────────────────────────────────────────┘
┌─ L2 事實正確性（怕）─────────────────────────────────┐
│  ⚠ ChatGPT 說你營業至 22:00，官網為 21:00           │
│  ⚠ Perplexity 把你歸為「居酒屋」，官網為「割烹」    │
│  ✓ 地址正確  ✓ 價位帶正確                            │
│      真值來源：官網（2026-09-05 快照）               │
└──────────────────────────────────────────────────────┘
┌─ L3 引用來源結構（產業洞察）─────────────────────────┐
│  AI 談論【信義區日式料理】時引用誰：                 │
│   愛食記 34% │ Google Maps 22% │ 官網 12% │ PTT 9%  │
│  你被引用的來源：Google Maps ×2、官網 ×0            │
│      母體中「官網被引用」的店家佔 41%，你不在其中    │
└──────────────────────────────────────────────────────┘
┌─ L4 缺口（陳述，不承諾）─────────────────────────────┐
│  排名前 10 的店家中，9 家有可索引的線上菜單頁        │
│  你沒有。                                            │
│      ↑ 這是相關，不是因果。母體 n=23                 │
└──────────────────────────────────────────────────────┘
```

### 3.3 每一層的競爭意義

| 層 | 回應你的哪個質疑 | 競品有嗎 | 為什麼他們補不上 |
|---|---|---|---|
| **L0 位置** | 「權重能代表什麼」→ **不需要權重** | ❌ | 需要整個母體 |
| **L1 相對變化** | 「誰認可我」→ **對照組本身就是說服力** | ❌ | 需要母體 × 多波 |
| **L2 事實正確性** | 「商家只在乎變現」→ **這攻「怕」不攻「貪」** | ⚠️ 部分 | 需要獨立真值表（A2） |
| **L3 引用結構** | 「權威」→ **產業級數據取代個人資歷** | ❌ | 需要產業樣本 |
| **L4 缺口** | 相容 D-007（陳述不承諾） | ✅ 都有 | **這層是唯一可被複製的**，所以不能靠它 |

**注意 L4 是唯一沒有防禦力的一層。** 而它正好是所有競品的主打（Hogiah「優化建議」、Peec「Recommended actions」、Profound「Aim」）。這是巧合嗎？不是——**因為那是唯一不需要母體就能做的層**。

### 3.4 明確不做的功能（六個月內）

| 不做 | 理由 |
|---|---|
| 情緒分析 | 六家全有，零差異化，且情緒對「AI 有沒有推薦我」的解釋力未驗證 |
| 內容生成 | 撞 D-007；且是 Hogiah 的定價主軸（NT$12,800 / 35 篇），正面對撞 |
| 多引擎擴充 | 純成本競賽。藍圖已鎖定三平台，**三平台差異本身就是研究產出（A5）** |
| 競品對比矩陣（自選競品） | 你有的是**母體**，比「使用者自己填三個競品」強得多。做了反而自我降級 |
| 帳號／訂閱／持續監測 | 在 §6 待決事項確定前做，會鎖死選擇 |
| 總分（單一數字） | 依 NR-3（H-006 敏感度）結果再決定。**若排名對權重敏感，就不該有總分** |

## 4. Roadmap：與白皮書三波綁定

**關鍵設計：產品的每一次能力躍升，都由白皮書的一波資料解鎖。不是兩條線，是一條線的兩個輸出。**

| 月 | 白皮書（主線） | 產品解鎖 | 新增工程量 |
|---|---|---|---|
| **0** | 凍結 sample_v1 / prompt_v1 / codebook_v1；**先計時跑 10 次確認人時可行** | — | 0 |
| **1** | 建 restaurant_master 真值表（A2） | **L2 事實正確性**可做 | 小（比對邏輯） |
| **1–2** | **第 1 波** 172 次；原始封存 | **L0 位置** + **L3 引用結構** 解鎖 | 小（百分位計算） |
| **2–3** | **第 2 波**；15% 雙重編碼 | **L1 相對變化** 解鎖（兩點成線） | 小 |
| **3–4** | **第 3 波**；鎖數分析；Jaccard / Kendall τ | **A5 平台差異**；穩定性可報告 | 0 |
| **4–5** | 白皮書撰寫 + 外部檢驗者 | 單店報告成型（L0–L4 全備） | 中（報告頁改版） |
| **5–6** | 發布 | **商業測試：實際接觸 10 家**，看有無人付費 | 0 |

**工程總量極小。** 你不需要蓋一個新產品——你需要在現有單站報告上，把「分數」換成「位置」，並接上母體資料表。

### 4.1 六個月後的延伸（母體複製）

這才是真正的複利。**方法論是可轉移的資產，母體是可複製的產能。**

```
母體 #1  信義區餐飲     → 驗證方法（白皮書 v1）
   ↓ 同一套 SOP、同一套 codebook、同一套管線
母體 #2  ?              → 第二份白皮書 + 第二個市場
   ↓
母體 #3  ?              → ...
```

每個新母體的**邊際成本遞減**（SOP 已凍結、管線已建、編碼手冊已寫），但**邊際價值遞增**（跨產業比較本身是新研究問題：「哪個產業的 AI 能見度落差最大」——這正好是 Charter H-005 的正式檢驗）。

> ⚠️ 母體 #2 的選擇是 §6 的待決事項，**不應該預設是餐飲的延伸**。理由見 §5.2。

## 5. 護城河的誠實評估

### 5.1 這是時間差護城河，不是永久護城河

我不會告訴你這是無法攻破的。拆解一下對手要複製需要什麼：

| 要素 | 複製難度 | 說明 |
|---|---|---|
| 跑 140 個站的查詢 | 🟢 **極低** | 用 API 幾乎免費。Hogiah 明天就能做 |
| 建抽樣框（TFDA → 篩選 → 去重 → 人工查核營業） | 🟠 中 | 純勞力，但沒人想做 |
| **實體真值表（別名、分店、共用網域歸屬）** | 🔴 **高** | 你自己的 `entity-master` 已經踩過這個坑（共用網域必須明確對應 owned URL）。這是最硬的一塊 |
| **真實 UI 操作而非 API** | 🔴 **高** | 藍圖 §D 要求台灣 IP、繁中、桌面網頁、專用帳號、關閉記憶、不追問。**SaaS 無法自動化到這個程度** |
| 盲式編碼 + 15% 複編一致率 | 🟠 中 | 需要紀律，不需要技術 |
| **連續三波不中斷** | 🔴 **高** | 這是唯一真正需要時間的東西，**買不到** |

**結論**：母體優勢的來源不是技術，是**累積的勞動與紀律**。這對你有利的地方在於——這正是有融資的競爭對手**最不願意做**的事（ROI 低、不能加速、無法用工程解決）。

**但要誠實**：這給你的是 **6–12 個月的領先**，不是永久。若 Hogiah 決定認真做一次產業普查，他們做得到。你的優勢是他們**沒有動機**這麼做（他們的定價階梯建在文章篇數上，普查不會增加 ARPU）。

### 5.2 最大的風險：母體選錯了

**這是我認為整份策略最脆弱的地方，必須說清楚。**

- Charter H-005（餐飲業落差最大、最易被打動）標為**使用者臆測**，至今未驗證。
- 餐飲業的付費意願**可能是所有產業裡最低的**：低毛利、老闆時間被廚房佔滿、數位化程度低、決策人＝執行人。
- **反向線索**〔C1｜`COMPETITIVE_INTEL` S001, S002〕：Hogiah 自營品牌 DearDear 是**美業**；其解決方案頁把「美容與個人照護」「醫療與健康」排在前二，餐飲排第三。一個天天面對台灣市場的競爭者，**選了美業當主戰場**。

**這不代表餐飲是錯的**，但代表：

> **白皮書的最佳母體（餐飲：樣本易得、公開資訊完整、TFDA 有登錄資料集）
> 和商業上最佳的母體（可能是醫美／牙醫／專業服務：高毛利、高面子、高競爭）
> 可能不是同一個。**

**建議的處理方式**：不要為了商業去換掉白皮書的母體。餐飲的資料可得性是白皮書成立的基礎。正確作法是——

- 母體 #1（餐飲）＝ **驗證方法 + 產出白皮書 v1**，商業層只做小規模測試（接觸 10 家，看反應）
- 母體 #2 的選擇 ＝ **依 NR-2 訪談結果決定**，明確以付費意願為選擇準則

這樣你不會用一個未驗證的臆測（H-005）同時賭掉研究與商業。

### 5.3 還有一個沒有解決的東西

L0–L4 全部是**觀測**。它們都沒有回答「我照做會不會變好」。

這仍然是 `ROADMAP_OPTIONS` §0.3 指出的空洞：**零筆介入證據**。

母體基準線讓你能說「你排第 17」，但不能說「照這樣做會變第 10」。要能說後面那句，只有 NR-1（介入實驗）。

**而 L1（相對變化）＋母體，正好讓介入實驗第一次變得可解讀**——因為你終於有對照組了。這兩件事是互相成立的：

```
NR-1 介入實驗  ──需要──►  母體對照組  ──來自──►  白皮書波次
        ▲                                              │
        └──────────  讓分數有意義  ◄──────────────────┘
```

**所以 NR-1 不該現在單獨做，應該與第 1 波同時做**：第 1 波建立基線 → 你的自有站與 2–3 個配合站做介入 → 第 2 波量測，同時得到母體漂移作對照。

**這是本檔唯一一項對先前建議的修正**：`ROADMAP_OPTIONS` 建議 NR-1「立刻做」，但更好的作法是**與波 1 同步**，否則沒有對照組，介入結果一樣不可解讀。

## 7. 一句話總結

**白皮書不是產品的前置作業，白皮書就是產品的資料工廠。**

競品賣「你的分數」，你賣「你在母體中的位置與相對變化」。
前者是功能，會被補丁抹平；後者是分母，補丁補不出來。

你缺的不是功能，是**第一波資料**。

## 8. 本檔限制

- 「商家會為母體位置付錢」——**未驗證假設**，無任何第一手證據（NR-2 未執行）。
- 「餐飲業付費意願低」——**推論**，依據是 Hogiah 的產業排序（C1 廠商線索）與一般商業常識，**不是實證**。
- Dashboard 五層結構**未經任何使用者測試**，是依據競品缺口反推的設計，不是需求驗證的結果。
- 人時成本**未實測**（藍圖真實 UI 操作 172 次／波）。§4 的月份配置在計時試跑前只是估計。
- 未做法律評估（D-k）。
