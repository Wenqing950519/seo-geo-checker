### 2026-07-26 構念先於測量（P0 charter 訪談）

- **核心概念**（Agent 版本，**請用自己的話改寫後才算數**）：

  1. **構念先於測量。** 順序是 `構念定義 → 操作化 → 變項 → 構面 → 權重 → 實作`。GeoCheck 從第二步開始做，跳過了第一步，所以權重只能憑感覺。這不是疏忽，是順序錯了。
  2. **效度是「測到的是不是你想測的」。** Hunterest 站內準備度 87 卻完全沒被 Perplexity 提及——這不是資料異常，是在提示「站內準備度」可能根本沒在測可見度。

### 2026-09-04 全站去 AI 樣板化與純粹中文排版重構

- **情境**：首頁、白皮書與品牌規範手冊充斥常見於 AI 生成（Vibe Coding）的裝飾性全大寫英文字（例如 `WHAT WE MEASURED`、`CORE SIGNAL`、`GOVERNANCE & BOUNDARIES`、`PILLAR 1`），造成中英文混搭割裂與樣板廉價感。
- **核心概念**（Agent 版本，**請用自己的話改寫後才算數**）：
  1. **區分「專業技術名詞」與「裝飾性填充英文」**：具備國際標準的技術詞（`FAQ`、`HTTP`、`JSON-LD`、`Schema.org`、`v1.0.0`）予以保留；但純粹用作卡片頂部的無意義英文眉標屬於視覺噪音，應全面剔除或正名為在地化中文（如「核心推薦信號」、「面向一 · 產品核心指標」）。
  2. **無噪音的視覺層級（Hierarchy without Noise）**：中文版面應由字號、字重、灰階對比與留白節奏建立層次，而非依賴「中文字上方加一行全大寫英文」作為填充物，從而恢復研究型產品的自律與嚴肅感。
  3. **維護研究與商業契約不變**：視覺去樣板化的過程中，嚴格恪守底層合約約束（「這套分數是怎麼算的」、「不會當成 0 分」、65/35 雙軌架構），確保全站 25 組測試套件持續保持 100% 通過。

  - 各尺寸螢幕下首頁與白皮書的視覺流暢度

### 2026-09-09 Wave 0 基準量測與共用網域分層架構

- **情境**：啟動 2026 下半年信義區餐廳 AI 曝光度 Wave 0 基準量測前，需解決「70 家候選中 63 家合格，但去重根網域只有 49 個」的架構問題，並完成零 API 消耗的抓取預檢。
- **核心概念**（Agent 版本，**請用自己的話改寫後才算數**）：
  1. **分析單位兩層分離（店家實體層 vs 網站技術層）**：信義區餐飲業中，多家餐廳共用飯店（如君悅 7 家共用 `hyatt.com`）或商場網域。店家層為 63 家審核合格實體，網站技術層為 49 個去重根網域。必須透過 Entity Master 進行精確門市 URL 映射，絕不可為了湊整數隨意塞入未經審核的孤立網域。
  2. **AI 搜尋的「第三方媒體依賴」現象**：在無品牌推薦情境中，Perplexity 幾乎 100% 引用食尚玩家、窩客島、PopDaily 等第三方整理包，導致官方網站引用率為 0.0%。這實證了 AI Trust Index 將「答案採用（65%）」與「官方來源引用（35%）」拆開衡量的必要性。
  3. **缺失值處理原則（Research Integrity）**：爬取失敗的站點（如被 WAF 攔阻或 DNS 失效），其站內準備度與 AI 分數標記為 `failed/unknown`，嚴禁給 0 分，避免人為扭曲產業統計平均值。
- **我能解釋到什麼程度**：能說明為何 63 家合格門市實體自然對應 49 個獨立根網域，以及為何鼎泰豐在第 1 題被採用但來源引用率為 0% 時計算為 32.5 分（50% × 65% + 0% × 35%）。
- **仍需人工驗證**：
  - 11 家受限站點的 WAF 特徵（萬豪、君悅、海底撈等）是否在 Wave 1 需導入動態渲染。
  - 爬蟲預檢與 API 呼叫分離的成本效益。
- **下次遇到類似問題我會怎麼做**：在資料集凍結前，先透過腳本跑一次 Entity Master 覆蓋率預檢（`assertReviewedEntityCoverage`），確保沒有未審核網域或 URL 協定不一致。

### 2026-09-09 題目設計的真實性與消除地板效應（Floor Effect）

- **情境**：Wave 0 初始題組因機械式限制（「晚餐預算 500 到 999 元」）直接排除了信義區高端牛排、景觀與精緻餐廳，導致 94.7% 站點得 0 分；隨後升級為約會慶生、大眾聚餐、火鍋燒肉三大真實消費搜尋情境並重新量測。
- **核心概念**（Agent 版本，**請用自己的話改寫後才算數**）：
  1. **真實搜尋情境才是有效尺標**：消費者向生成式 AI 提問帶有強烈動機（約會浪漫、朋友聚餐、特定品類渴望）。若題目的設定包含人為僵化限制（如偏離受測主體的價格區間），會產生嚴重的「地板效應（Floor Effect）」，導致 95% 樣本集體得 0 分，變異數消失使分組比較完全失效。
  2. **情境化 GEO（Contextual GEO）**：餐廳在 AI 搜尋中的能見度是「分場景」競爭的。題組升級為三大真實情境後，WILDWOOD（約會慶生）、饗食天堂（大眾聚會）、合‧shabu（頂級鍋物）分別在各自所屬的場景破零取得 21.5 分（33% 採用率）。
  3. **跨國品牌的「雙面數位矛盾」**：君悅酒店旗下的「寶艾西餐廳」在約會慶生題中多次被 AI 選為米其林求婚首選（AI 心智極強），但其官方網域 `hyatt.com` 卻部署 Akamai WAF 防火牆阻擋了一般伺服器爬蟲。這生動展現了「品牌聲量深植於外部媒體，但第一方數位資產卻封閉於防火牆後」的真實企業生態。
- **我能解釋到什麼程度**：能解釋為何題組升級至 v2.0 後能消除地板效應，以及為何官方來源引用率依然是 0.0%。
- **仍需人工驗證**：
  - 未破零的頂級牛排館（莫爾頓、教父、S&W），在各情境回傳文本中是否因符號處理（如 `&`）而影響別名命中。
  - 是否需要在正式報告中進一步增加第 4 題商務宴客情境。
- **下次遇到類似問題我會怎麼做**：在確定研究題庫前，先以 1~2 筆代表性站點呼叫 API 觀察真實自然語言在 AI 搜尋引擎中的答案樣貌，確保題目覆蓋不同客單價與料理定位，避免人為製造統計盲點。
