### 2026-07-26 構念先於測量（P0 charter 訪談）

- **情境**：原本只是要補齊 charter 的 13 個 TODO，過程中發現這些 TODO 不是獨立的空格，而是同一個結構性缺口的症狀。訪談結束時決定全面重構，並確立 P0→P1→P2→P3 四階段。

- **核心概念**（Agent 版本，**請用自己的話改寫後才算數**）：

  1. **構念先於測量。** 順序是 `構念定義 → 操作化 → 變項 → 構面 → 權重 → 實作`。GeoCheck 從第二步開始做，跳過了第一步，所以權重只能憑感覺。這不是疏忽，是順序錯了。
  2. **效度是「測到的是不是你想測的」。** Hunterest 站內準備度 87 卻完全沒被 Perplexity 提及——這不是資料異常，是在提示「站內準備度」可能根本沒在測可見度。
  3. **研究產出與產品產出要分開。** 原始訊號屬研究層（不需要權重），單一分數屬產品層（才需要權重）。現行架構把兩者綁在 `geo-assessment.js`，是權重爭議的結構性根源。
  4. **主動揭露邊界比硬撐結論可信。** A4（引用→獲客）做成探索性分析並列出四項限制，比宣稱因果更有說服力。
  5. **charter 的價值在說真話，不在填滿。** 沒想清楚的欄位標「未定」，比編一個看起來完整的答案更有用。

- **我能解釋到什麼程度**：〔待自評〕
