個人方案通常只需信箱或手機符合驗證資料；商務資料表與頁內摘要對統編的呈現略有差異。商務送件建議一併公開合法名稱、統編與有效聯絡資訊，避免只按最少欄位準備。不得編造統編、店面或證明照片。

## 收款選擇與成本
若首版只收臺灣信用卡的一次性付款，可先評估一般賣家的全方位金流導轉頁；不因名稱叫 Platform 就申請綠界「特約合作平台商」或代收付服務。實際承作仍依綠界個案審核。[產品與申請入口](https://www.ecpay.com.tw/Business/payment_standard)

一般賣家國內信用卡公告費率為 2.75%，最低手續費 5 元（未稅），另有每筆 1 元處理費（含稅）；手續費另加 5% 營業稅。30 日收款額度公告為個人 20 萬、商務 50 萬。特約賣家另有設定費、年費與議定條件，首頁促銷 1.68% 不可當成本案已取得費率。[現行費率](https://www.ecpay.com.tw/Business/payment_fees)

小額用量不能逐次任意送信用卡交易：綠界限制單筆金額，且明示不能加收刷卡手續費或因金額小拒絕刷卡。實際最低金額要查會員「合約及費率」，不能把自行推算的 6 元當核定值。[單筆金額限制](https://support.ecpay.com.tw/4804/)

成本試算只能幫助決定帳單結算方式，不能變成消費者的刷卡附加費。若採彙整帳單，所有付款方式均依相同、事前公開的計量與結算政策，不只限制信用卡。

## 預付可行性與「實支實付」的定義
D-051 確認按用量取代訂閱；D-053 已確認個人一般賣家與預付優先。計價單位及價格仍未確認。先前 `PRICING_MODEL_2026-09-12.md` §10.2 是「API 額度傾向適用禮券規範」的未確認推論，且已註明須律師確認，不是禁止預付的法律結論。

已查證：[現行綠界會員服務規範](https://support.ecpay.com.tw/10098/)（115-04-30 生效）第一節第 8 款要求遞延性商品／服務依法辦理並揭露履約保障，電子儲值型禮券須提供餘額查詢。規範提到此類交易，不能反推本案已可由個人一般賣家承作；綠界代收款的保管安排也不能未經確認便當成商家對未使用服務的履約保障。

法律分類須分開：[電子支付機構管理條例第 3 條](https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=G0380237&flno=3)對多用途支付及指定人提供商品／服務憑證有區分。僅用於本平台自有服務、不可轉讓或支付第三方，是本案擬採的範圍，不等於已確認免除其他消保義務。[商品（服務）禮券規範](https://www.ey.gov.tw/File/3CA2809FE5053D1?A=C)另有行業適用範圍；若本案適用，須辦理至少一年履約保障等事項，不能只貼條款便視為完成。API 服務的確切分類、保障方式與個人承作資格，仍待綠界及必要的主管機關確認。

| 選項 | 實際交易 | 優點 | 最強反方與必要條件 |
|---|---|---|---|
| 預付服務額度、用多少扣多少（使用者首選） | 先付款形成可使用餘額，再逐次扣除 | 限制墊款風險，適合機器 API | 屬預付服務的事實不能隱瞞；個人承作、履約保障成本及分類尚待確認 |
| 按量結算、每張帳單手動付款（備案） | 完成的有效用量彙整成新台幣帳單，使用者確認後一次付清 | 沒有長期未使用的預付餘額 | 平台墊付成本、有壞帳；須另定信用與結算規則，不自動切換 |
| 按量帳單、綁卡自動付款 | 用量彙整後向已授權卡片扣不同金額 | 使用摩擦少 | 需要綁卡服務資格、授權、失敗與爭議管理；不等同一般定期定額訂閱 |

首版草案依使用者授權採一般退款規則：限自有服務／原帳戶、不轉讓、不自動儲值；實付餘額無效期、未使用款可退、不扣退款費、停業返還。這些是商家政策草案，尚無餘額帳本或退款實作；名稱改為「點數」不會改變交易實質。

## 個人申請與稅務
使用者確認目前無營業登記，採個人申請，不導入原訂閱頁的自動電子發票承諾。但個人金流資格、稅籍登記及統一發票義務是不同問題。[財政部規定](https://www.etax.nat.gov.tw/etwmain/tax-info/network-transaction-taxtation-area/regulation)自 114-01-01 起，網路銷售勞務當月達新台幣 5 萬元即應辦理稅籍登記；未達者的暫免條件仍須符合，不能單憑未登記推論免辦。是否使用統一發票另依規模、業別及國稅局核定，未達起徵點也仍有所得申報問題。[官方 Q&A](https://www.etax.nat.gov.tw/etwmain/tax-info/network-transaction-taxtation-area/q-and-a)

尚未核對使用者全部網路銷售額，不能在網站宣稱已核定免用統一發票。付款紀錄不等同統一發票；上線前應確定實際可提供的憑證並揭露。

「按用量定價」與「上游成本原價轉付」也不同。若真要成本轉付，需逐項定義模型費、搜尋工具費、重試、匯率時點、平台費、稅及小數處理。現有 provider_cost 可能只有範圍或 unknown，不能拿估計上界當已發生、可向客戶收取的確定成本。
