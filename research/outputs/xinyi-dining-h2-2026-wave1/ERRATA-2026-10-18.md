# Wave 1 原始證據換行轉換更正

核對日期：2026-10-18（Asia/Taipei）。本紀錄說明 2026-10-17 推送至 GitHub 的 Wave 1 檔案中，哪些檔案的位元組已與 `manifest.json`（2026-10-15T06:42:01Z 封存）不符、已如何修復，以及哪些無法還原。`manifest.json` 與 `site-evidence/fetch-events.jsonl` 不修改，仍代表收錄當時的雜湊。

## 原因

2026-10-17 把 Wave 1 提交進 Git 時，repo 沒有 `.gitattributes`，本機又設定 `core.autocrlf=true`。Git 把它判定為文字的檔案中，CRLF 都在提交時改成 LF。提交前的整理流程（stash 未追蹤檔、再由 Git 取回）又把本機工作樹的原檔換成 Git 版本，所以本機也沒有留下原始位元組。在 LS-Labs 工作區與系統暫存目錄以雜湊搜尋，也找不到其他相符的副本。

更正：repo 根目錄新增 `.gitattributes`，將 `research/outputs/**` 標為 `-text`，此後研究輸出一律按原位元組保存，不再轉換換行。

## 對研究結果的影響

- Wave 1 的抓取判定、實體對應與分數都在 2026-10-15 依原始位元組產生，不受本次轉換影響，也不需要重算。現存檔案少掉的只有行尾 CR，HTML 文字、標題、連結與結構化資料的內容不變。
- 這 18 份不能再宣稱「與收錄時逐位元組相同，可用封存雜湊驗證」。引用時，應寫成「內容僅經行尾正規化（CRLF→LF），原始雜湊見 `fetch-events.jsonl`」。
- 若之後需要這些網址可逐位元組驗證的原始回應，只能重新抓取；新回應代表新的觀測時間，不能取代 2026-10-15 的紀錄。
